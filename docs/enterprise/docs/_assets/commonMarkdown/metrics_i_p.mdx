## `iceberg_amm_check_duration_ms_total`

- Unit: Millisecond
- Type: Cumulative
- Labels: `catalog`
- Description: Total time spent on Iceberg auto metadata maintenance check passes (listing candidate tables and deciding whether maintenance is due).

## `iceberg_amm_check_total`

- Unit: Count
- Type: Cumulative
- Labels: `catalog`
- Description: Total number of Iceberg auto metadata maintenance check passes.

## `iceberg_amm_execute_duration_ms_total`

- Unit: Millisecond
- Type: Cumulative
- Labels: `catalog`, `action` (`expire_snapshots`, `remove_orphan_files`, or `rewrite_manifests`)
- Description: Total time spent executing Iceberg auto metadata maintenance actions.

## `iceberg_amm_execute_total`

- Unit: Count
- Type: Cumulative
- Labels: `catalog`, `action` (`expire_snapshots`, `remove_orphan_files`, or `rewrite_manifests`), `status` (`success`, `skipped`, `failed`, or `partial`)
- Description: Total number of Iceberg auto metadata maintenance executions. `skipped` means the action ran but had nothing to do (no snapshots to expire, manifests to compact, or orphan files to remove); `partial` means some work was applied before a failure (part of the orphan files were already deleted). The ratio against `iceberg_amm_check_total` indicates how many maintenance tasks each check pass actually triggers.

## `iceberg_planning_latency_ms`

- Unit: Millisecond
- Type: Histogram
- Labels: `catalog`
- Description: Histogram of Iceberg query split-planning latency per catalog (sourced from Iceberg's own `totalPlanningDuration`, i.e. manifest planning only). Recorded for every Iceberg query regardless of whether auto metadata maintenance is enabled. Use it to observe the planning performance trend as metadata maintenance takes effect, e.g. `rate(iceberg_planning_latency_ms_sum[5m]) / rate(iceberg_planning_latency_ms_count[5m])` for the time-windowed average. Reflects mainly `rewrite_manifests` effectiveness; incremental-scan planning is not included.

## `iceberg_delete_bytes`

- Unit: Bytes
- Type: Cumulative
- Labels: `delete_type` (`position`, `deletion_vector`, or `metadata`)
- Description: Total deleted bytes from Iceberg `DELETE` tasks. For `metadata` delete, this represents the size of deleted data files. For `position` delete, this represents the size of position delete files created.

## `iceberg_delete_duration_ms_total`

- Unit: Millisecond
- Type: Cumulative
- Labels: `delete_type` (`position`, `deletion_vector`, or `metadata`)
- Description: Total execution time of Iceberg `DELETE` tasks in milliseconds. The duration of each task is added after it ends. `delete_type` distinguishes the delete methods.

## `iceberg_delete_rows`

- Unit: Rows
- Type: Cumulative
- Labels: `delete_type` (`position`, `deletion_vector`, or `metadata`)
- Description: Total deleted rows from Iceberg `DELETE` tasks. For `metadata` delete, this represents the number of rows in deleted data files. For `position` delete, this represents the number of position deletes created.

## `iceberg_delete_total`

- Unit: Count
- Type: Cumulative
- Labels:
  - `status` (`success` or `failed`)
  - `reason` (`none`, `timeout`, `oom`, `access_denied`, `unknown`)
  - `delete_type` (`position`, `deletion_vector`, or `metadata`)
- Description: Total number of `DELETE` tasks that target Iceberg tables. The metric is incremented by 1 after each task ends, regardless of success or failure. `delete_type` distinguishes the delete methods: `position` (generates position delete files), `deletion_vector` (writes Iceberg V3 deletion vectors), and `metadata` (metadata-level delete).
