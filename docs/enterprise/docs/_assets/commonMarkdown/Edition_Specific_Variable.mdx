### enable_jdbc_agg_push_down

* **Scope**: Session
* **Description**: Controls whether the optimizer can push eligible aggregate operations on JDBC catalog tables down to the JDBC data source. When this variable is set to `true`, the system may send supported aggregate expressions, GROUP BY keys, and HAVING predicates to the remote database as part of the JDBC scan SQL. This pushdown can be combined with JDBC join and project pushdown when the related session variables are also enabled. Set this variable to `false` to keep aggregate execution in the system.
* **Default**: `true`
* **Data Type**: boolean
* **Introduced in**: v4.1

### enable_jdbc_join_push_down

* **Scope**: Session
* **Description**: Controls whether the optimizer can push eligible joins on JDBC catalog tables down to the JDBC data source. When this variable is set to `true`, the system may merge supported joins, pushable predicates, and required output columns from compatible JDBC scans into one remote SQL query. Set this variable to `false` to keep join execution in the system.
* **Default**: `true`
* **Data Type**: boolean
* **Introduced in**: v4.1

### enable_jdbc_project_push_down

* **Scope**: Session
* **Description**: Controls whether the optimizer can push eligible projection expressions on JDBC catalog tables down to the JDBC data source. When this variable is set to `true`, the system may include supported column projections and expression projections in the remote JDBC SELECT list. This pushdown can be combined with JDBC join and aggregate pushdown when the related session variables are also enabled. Set this variable to `false` to compute projection expressions in the system.
* **Default**: `true`
* **Data Type**: boolean
* **Introduced in**: v4.1

### jdbc_predicate_pushdown_max_in_list_size

* **Scope**: Session
* **Description**: The maximum number of literal values in an `IN` predicate list that the system can push down to a JDBC data source. This variable applies to predicate and HAVING pushdown for JDBC scans. Set it to `-1` to impose no limit from the system side, `0` to disable pushdown for `IN` predicates, or a positive integer `N` to push down only `IN` lists with at most `N` values. You can tune this value to match limits in the remote database, such as Oracle `IN` list limits.
* **Default**: `-1`
* **Data Type**: int
* **Introduced in**: v4.1
