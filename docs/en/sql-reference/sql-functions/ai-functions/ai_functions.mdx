# AI functions

<Experimental />

AI functions call model services from SQL to generate, classify, extract, translate, summarize, and embed text. You can call these functions on constant text or process text columns in queries.

## AI Providers and AI functions

An AI Provider is a centrally managed model service configuration in the cluster. It stores an endpoint, protocol, default model, and optional credentials. AI functions obtain these settings from the Provider, so you do not need to repeat endpoints and credentials in SQL.

- `ai_embed` uses an `embedding` Provider.
- `ai_complete` and the other text helper functions use a `chat` Provider.
- These AI functions currently require the Provider to use the `openai` protocol. The endpoint and model must also support the corresponding chat or embedding capability.

When calling a function, you can specify a Provider with `provider` or use the cluster default Provider of the corresponding type. Defaults are maintained independently for each type. If you omit `model`, the selected Provider's default model is used. You can also explicitly specify another model supported by the service.

For Provider creation, configuration properties, and management syntax, see [CREATE AI PROVIDER](../../sql-statements/cluster-management/ai_provider/CREATE_AI_PROVIDER.md). For default settings, see [SET DEFAULT AI PROVIDER](../../sql-statements/cluster-management/ai_provider/SET_DEFAULT_AI_PROVIDER.md).

## AI function privileges {/* #ai-function-privileges */}

Calling an AI function requires both types of usage privileges:

- **Function privilege**: Allows use of the corresponding AI function.
- **Provider privilege**: Allows access to the Provider selected for this call. This privilege is also checked when using a default Provider.

Neither privilege replaces the other. Managing Providers requires SYSTEM OPERATE. Provider management privileges do not mean that ordinary users have usage privileges on functions and Providers. Privileges on the tables, columns, and views involved in the query still apply.

For details, see [AI privilege items](../../../administration/user_privs/authorization/privilege_item.md#ai-function-privileges). For the syntax to grant, revoke, and view privileges, see [GRANT](../../sql-statements/account-management/GRANT.md#ai-functions-and-providers), [REVOKE](../../sql-statements/account-management/REVOKE.md#ai-functions-and-providers), and [SHOW GRANTS](../../sql-statements/account-management/SHOW_GRANTS.md), respectively.

## Getting started

The following examples use the OpenAI-compatible API of Alibaba Cloud Model Studio (Bailian) in the Beijing region. Activate the model service, replace `YOUR_DASHSCOPE_API_KEY` with an API key for the Beijing region, and run the examples with an account that has Provider management privileges and usage privileges on the corresponding functions and Providers.

### Chat Provider: generate text

Create a chat Provider using the `qwen-plus` model, then call `ai_complete`:

```sql
CREATE AI PROVIDER bailian_chat TYPE chat
PROPERTIES (
    "endpoint" = "https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions",
    "protocol" = "openai",
    "model" = "qwen-plus",
    "api_key" = "YOUR_DASHSCOPE_API_KEY"
);

-- Explicitly specify the Provider and use its default model.
SELECT ai_complete(
    prompt => 'Explain what columnar storage is in one sentence.',
    provider => 'bailian_chat',
    options => json_object('enable_thinking', false)
);

-- After setting the default chat Provider, you can omit provider in calls.
SET bailian_chat AS DEFAULT AI PROVIDER;

SELECT ai_complete(
    prompt => 'Explain what columnar storage is in one sentence.',
    options => json_object('enable_thinking', false)
);
```

### Embedding Provider: generate text embeddings

Create an embedding Provider using the `text-embedding-v4` model with 256 output dimensions, then call `ai_embed`:

```sql
CREATE AI PROVIDER bailian_embedding TYPE embedding
PROPERTIES (
    "endpoint" = "https://dashscope.aliyuncs.com/compatible-mode/v1/embeddings",
    "protocol" = "openai",
    "model" = "text-embedding-v4",
    "dimensions" = "256",
    "api_key" = "YOUR_DASHSCOPE_API_KEY"
);

-- Explicitly specify the Provider to generate a text embedding.
SELECT ai_embed(
    input => 'Columnar storage is suitable for analytical queries.',
    provider => 'bailian_embedding'
);

-- Set the default embedding Provider without affecting the default chat Provider.
SET bailian_embedding AS DEFAULT AI PROVIDER;

SELECT ai_embed('Columnar storage is suitable for analytical queries.');
```

For complete function syntax, argument rules, and examples, see [AI text functions](ai_text_functions.md). Model calls send input text to the Provider's endpoint. Choose a service according to your data egress requirements, and consider query row counts, latency, and invocation costs.

## Reducing AI input rows {/* #reducing-ai-input-rows */}

For an `ORDER BY ... LIMIT` query with a positive `LIMIT` and no `OFFSET`, StarRocks can select candidate rows before
evaluating an AI projection when the ordering columns pass through that projection and any intervening ordinary
Project unchanged.

[`ai_topn_pushdown_max_global_limit`](../../System_variable.md#ai_topn_pushdown_max_global_limit) selects the
strategy for SQL `LIMIT N`:

- `N` at or below the threshold (default `1000`): a global candidate TopN limits input to the rewritten AI projection
  to at most `N` rows.
- `N` above the threshold: a local candidate TopN limits input to that AI projection to at most `N` rows per fragment
  instance, not per BE or pipeline driver.

The global strategy can trade cross-instance AI parallelism for a global row bound. The local strategy avoids an
additional global gather before AI execution, although local merging can reduce parallelism within an instance.
Both retain the original TopN above the AI projection to preserve output order and limit. Use `EXPLAIN` to inspect
the resulting plan.

These bounds apply to the rewritten AI projection, not all AI work in a query: an inner nested AI call may still
process more rows. They are not HTTP request or token limits. Pruned rows do not execute AI calls.

The optimization does not move TopN below AI calls needed for ordering or filtering, cross existing limits or unsafe
projection and predicate barriers, or apply to partitioned TopN, `RANK`, or `DENSE_RANK`.

### Selecting the strategy

The threshold supports `SET`, `SET GLOBAL` for future sessions, and statement-level `SET_VAR` hints without restarting.
It does not affect queries without an AI projection. Setting it to `0` selects local-only pruning, not disabled pruning.

```sql
-- Use global pruning for LIMIT <= 1000, and local pruning for larger limits.
SET ai_topn_pushdown_max_global_limit = 1000;
-- Use local-only pruning.
SET ai_topn_pushdown_max_global_limit = 0;
```
