## Reuse other services to control access to external tables

For External Catalog, you can reuse external services (such as Hive Service) for access control. StarRocks supports matching different Ranger external services for different Catalogs. When users access an external table, the system implements access control based on the access policy of the Ranger Service corresponding to the external table. The user permissions are consistent with the Ranger user with the same name.

1. Copy Hive's Ranger configuration files [ranger-hive-security.xml](https://github.com/StarRocks/ranger/blob/master/hive-agent/conf/ranger-hive-security.xml) and [ranger-hive-audit.xml](https://github.com/StarRocks/ranger/blob/master/hive-agent/conf/ranger-hive-audit.xml) to the `fe/conf` file of all FE machines. Make sure Ranger's IP and port are correct.
2. Restart all FE machines.
3. Configure External Catalog.

   - When you create an External Catalog, add the property `"ranger.plugin.hive.service.name"`.

      ```SQL
        CREATE EXTERNAL CATALOG hive_catalog_1
        PROPERTIES (
            "type" = "hive",
            "hive.metastore.type" = "hive",
            "hive.metastore.uris" = "thrift://xx.xx.xx.xx:9083",
            "ranger.plugin.hive.service.name" = "<ranger_hive_service_name>"
        )
      ```

   - You can also add this property to an existing External Catalog.
  
       ```SQL
       ALTER CATALOG hive_catalog_1
       SET ("ranger.plugin.hive.service.name" = "<ranger_hive_service_name>");
       ```

​    This operation changes the authentication method of an existing Catalog to Ranger-based authentication.

4. (Optional) Prefix the database name with the catalog name. This applies to every External Catalog that sets `ranger.plugin.hive.service.name`, such as Hive, Iceberg, and Hudi catalogs.

   The Ranger Hive Service only knows `database`, `table`, and `column`. It has no catalog level, so when several External Catalogs share one Hive Service (for example, several AWS Glue catalogs), a database that exists in more than one catalog matches the same policies. Set the property `"ranger.plugin.hive.catalog_prefix.enabled"` to `"true"` on such a catalog, and StarRocks sends `<catalog_name>_<database_name>` as the `database` resource to Ranger instead of the bare database name. For example, a query against `glue_prod.sales.orders` is checked against a Ranger policy whose database is `glue_prod_sales`.

   ```SQL
   CREATE EXTERNAL CATALOG glue_prod
   PROPERTIES (
       "type" = "hive",
       "hive.metastore.type" = "glue",
       "aws.glue.region" = "us-west-2",
       "ranger.plugin.hive.service.name" = "<ranger_hive_service_name>",
       "ranger.plugin.hive.catalog_prefix.enabled" = "true"
   );

   -- Or on an existing catalog. The new value takes effect when the statement returns.
   ALTER CATALOG glue_prod
   SET ("ranger.plugin.hive.catalog_prefix.enabled" = "true");
   ```

   - Valid values are `true` and `false`. Any other value makes CREATE or ALTER CATALOG fail.
   - When the property is not set, the catalog follows the FE configuration item `ranger_hive_catalog_prefix_enabled` (default `false`). Catalogs that do not set `ranger.plugin.hive.service.name` ignore this property.
   - The separator between the catalog name and the database name is the FE configuration item `ranger_hive_catalog_prefix_separator` (default `_`). It is global because every catalog that shares one Ranger Service must use the same separator.

### Create a Ranger integration

1. Sign in to the [PhoenixAI Cloud console](https://cloud.celerdata.com/login).

2. In the left-side navigation pane, choose **Integration Hub**.

3. On the **Integration Hub** page, click the **Apache Ranger** card.

4. On the **Apache Ranger** page, click **Create Configuration**.

5. On the **Create Ranger Configuration** dialog box, configure as follows:

   a. Enter a name for the configuration in the **Name** field.

   b. Choose the access control scope that Ranger can manage. If you choose **All catalogs**, Ranger will manage the access control to both the internal catalog (that is, `default_catalog` where the native data locates) and external catalogs. If you choose **External catalogs only**, Ranger will only manage the access control to external catalogs.

   c. Specify the location of `ranger-starrocks-security.xml` you uploaded to the remote storage.
