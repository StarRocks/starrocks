# AI 関数

<Experimental />

AI 関数は、SQL からモデルサービスを呼び出し、テキストの生成、分類、抽出、翻訳、要約、ベクトル化を行います。定数テキストに対して関数を呼び出すことも、クエリ内でテキスト列を処理することもできます。

## AI Provider と AI 関数

AI Provider は、クラスター内で一元管理されるモデルサービスの設定です。エンドポイント、プロトコル、デフォルトモデル、オプションの認証情報を保持します。AI 関数は Provider からこれらの設定を取得するため、SQL でエンドポイントや認証情報を繰り返し指定する必要はありません。

- `ai_embed` は `embedding` タイプの Provider を使用します。
- `ai_complete` とその他のテキスト補助関数は `chat` タイプの Provider を使用します。
- これらの AI 関数は現在、Provider が `openai` プロトコルを使用することを必要とします。エンドポイントとモデルも、対応するチャットまたは埋め込み機能をサポートしている必要があります。

関数の呼び出し時には、`provider` で Provider を指定するか、対応するタイプのクラスターデフォルト Provider を使用できます。デフォルトはタイプごとに独立して管理されます。`model` を省略すると、選択した Provider のデフォルトモデルが使用されます。そのサービスがサポートする別のモデルを明示的に指定することもできます。

Provider の作成、設定プロパティ、管理構文については [CREATE AI PROVIDER](../../sql-statements/cluster-management/ai_provider/CREATE_AI_PROVIDER.md) を、デフォルトの設定については [SET DEFAULT AI PROVIDER](../../sql-statements/cluster-management/ai_provider/SET_DEFAULT_AI_PROVIDER.md) を参照してください。

## AI 関数の権限 {/* #ai-function-privileges */}

AI 関数を呼び出すには、次の両方の使用権限が必要です。

- **関数の権限**: 対応する AI 関数の使用を許可します。
- **Provider の権限**: 呼び出しで選択された Provider へのアクセスを許可します。デフォルト Provider を使用する場合も確認されます。

一方の権限で他方を代替することはできません。Provider の管理には SYSTEM OPERATE 権限が必要です。Provider の管理権限があっても、一般ユーザーに関数と Provider の使用権限が付与されているとは限りません。クエリで使用するテーブル、列、ビューの権限も引き続き適用されます。

詳細は [AI の権限項目](../../../administration/user_privs/authorization/privilege_item.md#ai-function-privileges)を参照してください。権限の付与、取り消し、確認の構文については、それぞれ [GRANT](../../sql-statements/account-management/GRANT.md#ai-関数と-provider)、[REVOKE](../../sql-statements/account-management/REVOKE.md#ai-関数と-provider)、[SHOW GRANTS](../../sql-statements/account-management/SHOW_GRANTS.md) を参照してください。

## はじめに

次の例では、Alibaba Cloud Model Studio（Bailian）の北京リージョンの OpenAI 互換 API を使用します。モデルサービスを有効にし、`YOUR_DASHSCOPE_API_KEY` を北京リージョンの API キーに置き換えてください。Provider の管理権限と、該当する関数および Provider の使用権限を持つアカウントで実行してください。

### Chat Provider: テキストの生成

`qwen-plus` モデルを使用する chat Provider を作成し、`ai_complete` を呼び出します。

```sql
CREATE AI PROVIDER bailian_chat TYPE chat
PROPERTIES (
    "endpoint" = "https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions",
    "protocol" = "openai",
    "model" = "qwen-plus",
    "api_key" = "YOUR_DASHSCOPE_API_KEY"
);

-- Provider を明示的に指定し、そのデフォルトモデルを使用します。
SELECT ai_complete(
    prompt => '列指向ストレージとは何かを一文で説明してください。',
    provider => 'bailian_chat',
    options => json_object('enable_thinking', false)
);

-- デフォルトの chat Provider を設定すると、呼び出し時に provider を省略できます。
SET bailian_chat AS DEFAULT AI PROVIDER;

SELECT ai_complete(
    prompt => '列指向ストレージとは何かを一文で説明してください。',
    options => json_object('enable_thinking', false)
);
```

### Embedding Provider: テキストの埋め込みベクトルの生成

`text-embedding-v4` モデルを使用する embedding Provider を作成し、出力次元数を 256 に設定して、`ai_embed` を呼び出します。

```sql
CREATE AI PROVIDER bailian_embedding TYPE embedding
PROPERTIES (
    "endpoint" = "https://dashscope.aliyuncs.com/compatible-mode/v1/embeddings",
    "protocol" = "openai",
    "model" = "text-embedding-v4",
    "dimensions" = "256",
    "api_key" = "YOUR_DASHSCOPE_API_KEY"
);

-- Provider を明示的に指定して、テキストの埋め込みベクトルを返します。
SELECT ai_embed(
    input => '列指向ストレージは分析クエリに適しています。',
    provider => 'bailian_embedding'
);

-- デフォルトの embedding Provider を設定します。デフォルトの chat Provider には影響しません。
SET bailian_embedding AS DEFAULT AI PROVIDER;

SELECT ai_embed('列指向ストレージは分析クエリに適しています。');
```

関数の完全な構文、引数のルール、例については、[AI テキスト関数](ai_text_functions.md)を参照してください。モデル呼び出しでは、入力テキストが Provider のエンドポイントに送信されます。データ送信の要件に応じてサービスを選び、クエリの行数、遅延、呼び出し費用を考慮してください。

## AI 入力行数の削減 {/* #reducing-ai-input-rows */}

`LIMIT` が正で `OFFSET` を含まない `ORDER BY ... LIMIT` クエリでは、ソート列が AI 投影とその間の通常の Project を変更されずに通過する場合、StarRocks は AI 投影の評価前に候補行を選択できます。

[`ai_topn_pushdown_max_global_limit`](../../System_variable.md#ai_topn_pushdown_max_global_limit) は SQL の `LIMIT N` に応じて戦略を選択します。

- `N` がしきい値（デフォルト `1000`）以下の場合、グローバル候補 TopN により、書き換えられた AI 投影への入力を全体で最大 `N` 行に制限します。
- `N` がしきい値を超える場合、ローカル候補 TopN により、その AI 投影への入力を fragment instance ごとに最大 `N` 行に制限します。BE ごとや pipeline driver ごとの上限ではありません。

グローバル戦略では、全体の行数制限と引き換えにインスタンス間の AI 並列性が低下する場合があります。ローカル戦略は AI 実行前のグローバルな集約を追加しませんが、ローカルマージによってインスタンス内の並列性が低下する場合があります。どちらも AI 投影の上に元の TopN を保持し、出力順序と行数制限を維持します。`EXPLAIN` で実行計画を確認できます。

この上限は書き換えられた AI 投影に適用され、クエリ全体の AI 処理を制限するものではありません。ネストした内側の AI 呼び出しは、より多くの行を処理する場合があります。また、HTTP リクエスト数やトークン数の上限ではありません。除外された行では AI 呼び出しは実行されません。

この最適化は、ソートやフィルタリングに必要な AI 呼び出しの下に TopN を移動せず、既存の Limit や安全でない投影・述語の境界を越えません。パーティション化された TopN、`RANK`、`DENSE_RANK` にも適用されません。

### 戦略の選択

しきい値は、再起動なしで `SET`、以降のセッションに適用される `SET GLOBAL`、および文単位の `SET_VAR` ヒントで設定できます。AI 投影を含まないクエリには影響しません。`0` はローカルのみの削減を選択し、削減を無効にするものではありません。

```sql
-- LIMIT <= 1000 にはグローバル削減、それより大きい LIMIT にはローカル削減を使用します。
SET ai_topn_pushdown_max_global_limit = 1000;
-- ローカル削減のみを使用します。
SET ai_topn_pushdown_max_global_limit = 0;
```
